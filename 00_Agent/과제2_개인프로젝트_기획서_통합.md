## 2. 국내 식품 및 건강기능식품 표시사항 검토 기준 수립

국내 식품 및 건강기능식품 표시사항 검토 기준 수립

### 2. 개선하려는 업무와 이유

국내 표시기준이 강화됨에 따라 법규 제·개정 및 업데이트 사항이 누락되는 경우가 있어, 표시사항 검토 체크리스트를 통해 누락 사항이 발생하지 않도록 사전 예방하기 위함입니다.

### 3. 개선 목표

법규 고시사항을 우선 확인하여 표시사항에 반영함으로써 리스크 및 클레임을 예방합니다.

### 4. 기대 효과

담당자마다 달라지는 법규 해석 방식을 일치화하고, 누락 사항 없이 법규 사항을 반영하여 일관된 표시기준을 마련할 수 있습니다.

### 5. 사용할 기술

- 국가법령사이트를 비롯한 웹사이트에서의 데이터 수집 및 취합.
- 에이전트 등.

### 6. 구현 방향

최신 법규가 반영된 검토 기준에 표시 이미지를 넣으면 자동으로 스캔하여 누락·수정 사항을 파악하고 내용을 정리합니다.

## 4. 반품검수 통합조회 및 소비기한 점검

출처: 이미지 2

### 1. 프로젝트명

반품검수 통합조회 및 소비기한 점검

반품 검수, WMS 출고이력, 소비기한 재고, 유통기한 임박상품, 장기 미처리, 메모 업무를 한 프로그램에서 통합 조회하고 관리하는 업무 프로그램입니다.

### 2. 개선하려는 업무와 이유

반품재고 정보가 Google 검수데이터, WMS, 품고 등 여러 시스템에 분산되어 있어 담당자가 반복적으로 조회하고 건별로 확인해야 했습니다.

이 과정에서 처리시간이 길어지고, 미검수·장기 미처리·소비기한 임박상품의 확인 누락 가능성이 있었습니다.

### 3. 개선 목표

분산된 반품재고 데이터를 하나의 프로그램으로 통합하고, 반복적인 조회·점검 업무를 자동화하는 것이 목표입니다.

특히 검수상태, 미처리 건, 소비기한 임박상품을 빠르게 확인하고 필요한 건만 사람이 최종 조치하도록 개선합니다.

### 4. 기대 효과

여러 시스템을 오가며 반복 조회하던 업무를 하나의 프로그램으로 통합해 반품 처리과정을 단순화하고, 소비기한 관리와 반품 누락 가능성을 줄였으며 담당자별 확인 과정을 표준화했습니다.

또한 소비기한 임박상품의 온라인 판매 여부 확인을 자동화해 대상상품 12건을 19.5초 만에 조사하고, 판매중 7건·판매종료 5건을 판정했으며, 각 판정 사유와 상품 URL까지 함께 확인할 수 있도록 구현했습니다. (2026-09-03 실행 기준)

### 5. 사용할 기술

- 데이터 연동 + Windows 업무 프로그램 + 업무 자동화 + 웹 조회 + Agent 활용.
- Google/WMS/품고 데이터를 연동하고, PyQt 기반 프로그램에서 조회·캐시·웹 확인 기능을 구성합니다.
- 소비기한 임박상품의 반복 조사 단계에는 Agent를 활용합니다.

### 6. 구현 방향

검수정보 → WMS 출고지시 → 소비기한 재고 → 유통기한 임박 → 장기 미처리 → 메모장을 하나의 프로그램으로 통합합니다.

이후 소비기한 임박상품의 판매 여부와 고지상태 확인 같은 반복 조사 업무에 Agent를 활용하는 방향으로 구현합니다.

## 5. shopee_total_portfolio

출처: 이미지 3

### 1. 프로젝트명

shopee_total_portfolio

쇼피 인도네시아 성과 통합 및 재고·마케팅 최적화 에이전트 시스템

### 2. 개선하려는 업무와 이유

- **수작업 요일/시즌 분석의 병목:** 쇼피 셀러센터, 쇼피 인앱 광고, 메타 광고 등 규격이 모두 다른 Raw Data를 매번 내려받아 수동으로 환율(IDR/KRW)을 연산하고 수기 통합 정렬하는 병목 공수가 매우 큽니다.
- **채널 판매 결과의 실시간 확인 한계:** 데이터 통합 작업이 수기로 진행되다 보니 실시간으로 채널별 순매출을 확인하기 어렵고, 더블데이(Double Day) 및 페이데이(매월 25일) 프로모션일의 요일별 성과 추이를 즉각 판단하기 곤란합니다.
- **제품별 병목 진단 및 물류 리스크 방지 지연:** 노출 대비 장바구니 등록이 저조한 상품(상세페이지 보완 필요), 장바구니 등록 대비 구매 전환이 안 되는 상품(할인 쿠폰 필요) 등을 정량적으로 분류하여 마케팅 조치를 취하는 속도가 느립니다. 또한 안전 재고 미달 수량 및 남은 유통기한 일수를 매칭 대조하여 리스크를 예방하는 감시 체계가 부재합니다.

### 3. 개선 목표

- **데이터 가공 자동화:** 흩어진 세일즈/마케팅 Raw Data를 클릭 한 번으로 통합 마스터 엑셀(`combined_output.xlsx`)로 변환합니다.
- **실시간 대시보드 시각화:** KRW/IDR 이원 환율 토글, 프로모션일 필터, 안전 재고 및 유통기한 위험 경고등(주황색 한 가지 기준 강조)이 부착된 반응형 HTML 대시보드를 구축합니다.
- **멀티 에이전트 분석 연동:** 평일 대비 특수 데이의 성과 가중치 연산(요일/시즌 트렌드 분석기) 및 SKU 전환 장벽 라벨링(상품 관심도 탐지기)을 에이전트가 자동 수행하고, 매주 주간 분석 보고서 초안 마크다운을 자동 생성합니다.

### 4. 기대 효과

- **업무 가공 공수 단축:** 매주 평균 3~4시간 이상 소요되던 이종 데이터 병합, 환율 계산, 정합성 검증 작업을 10분 이내로 단순화하여 기획 리소스를 확보합니다.
- **광고 효율(ROAS) 극대화:** 가격 저항 상품과 상세페이지 개선 SKU를 실시간 식별하여 타겟 할인 쿠폰 및 프로모션 개편 등을 신속하게 파악 후 실행합니다.
- **재고/유통 리스크 사전 방지:** 안전재고량 부족과 유통기한 잔여 위험 SKU 정보를 시각 배지로 노출하여 미판매 재고 폐기 및 품절 리스크를 즉각 예방합니다.

### 5. 사용할 기술

- 데이터 수집 및 취합 자동화.
- Multiagent 시스템.
- HTML 기반 대시보드 구현.

### 6. 구현 방향

1. **Phase 1 — 데이터 취합 도구 개발:** 이원 환율 및 이형 데이터를 자동으로 규격화하여 표준 매핑 후 combined 마스터 파일을 쓰는 원클릭 프로그램 구축. (Day 2 과제 연계)
2. **Phase 2 — 실시간 모니터링 대시보드 배포:** 취합된 데이터를 읽어 매출 흐름, ROAS 성과, 안전 재고 부족 및 유통기한 임박 상품 정보를 한눈에 보여주는 HTML 대시보드 구축 및 배포.
3. **Phase 3 — 멀티 에이전트 리포팅 루프 세팅:** 총괄 메인 에이전트가 하위 서브에이전트를 통제하여 정량 보고서 초안을 조립하되, 기준 충돌이나 불확실성이 겹친 항목은 ‘사람 확인 대기’ 목록으로 안전하게 격리하여 사람이 최종 의사결정을 검수 및 결재하는 안전 반자동 프로세스 설계. (Day 3 과제 연계)

## 6. 쿠팡 로켓배송 발주 자동화

출처: 이미지 4

### 1. 프로젝트명

쿠팡 로켓배송 발주 자동화

### 2. 개선하려는 업무와 이유

기존 쿠팡 로켓배송 발주 업무는 미납 여부, 납품 유통기한, 입고 유형, 재고 현황 등 여러 항목을 순차적으로 수기 확인해야 하는 방식으로 진행됩니다.

확인 단계가 많아 담당자의 숙련도에 따라 업무 처리 편차가 발생하며, 담당자 부재 시 원활한 발주 대응에도 어려움이 있습니다.

더불어 쿠팡 신규 계정 추가 및 긴급발주 서비스 생성으로 인해 월 평균 발주 횟수가 기존 대비 2배 증가하면서, 반복적인 발주 업무를 효율적으로 처리할 수 있는 자동화의 필요성이 증가하여 해당 업무를 개선해보고자 합니다.

### 3. 개선 목표

- 발주에 필요한 각종 확인 항목을 자동으로 조회 및 검증.
- 단계별로 순차 확인하던 자료를 동시에 확인하여 업무 처리 시간 단축.
- 담당자 부재 시에도 동일한 기준으로 업무를 처리할 수 있도록 표준화된 발주 프로세스 구축.

### 4. 기대 효과

- 긴급발주 대응 건수 확대.
- 반복적인 확인 업무 자동화를 통한 발주 소요시간 단축.
- 담당자 부재 시에도 업무 대응이 가능한 업무 연속성 확보.
- 담당자의 숙련도에 따른 업무 편차를 줄이고 발주 프로세스 표준화.

### 5. 사용할 기술

서버 에이전트 및 EXE 기반 자동화 프로그램.

### 6. 구현 방향

발주서 및 실시간 유통기한별 재고 현황 자료를 다운로드하여 자동화 프로그램에 입력하면, 서버에서 재고 데이터를 가공하고 필요수량을 자동으로 산출하도록 구현합니다.

자동 산출된 결과를 담당자가 확인한 후, 수정 또는 추가 작업이 필요한 부분은 담당자가 최종 검토하고, 최종 확정된 자료를 기반으로 발주 업무를 진행할 수 있도록 구성합니다.

이를 통해 기존의 반복적인 자료 조회 및 수기 계산 과정을 자동화하고, 담당자는 결과 확인 및 예외 사항 처리에 집중할 수 있는 업무 구조를 구축합니다.

## 7. 수출 성분 검토 통합 대시보드

출처: 이미지 5 하단 ‘과제 2 · 개인 프로젝트 기획서’

### 기획 배경

등록된 4개 에이전트를 실제로 돌려본 결과를 바탕으로 범위를 좁혔습니다. 어떤 제품을 어느 나라 기준으로 검토할지는 사람만 판단할 수 있는 영역이라 자동화 대상에서 빼고, 대신 librarian 하나만 자동화해 취합본을 항상 최신으로 유지한 뒤 그 위에 대시보드를 놓습니다.

### 1. 프로젝트명

수출 성분 검토 통합 대시보드 — 취합본 자동 갱신 + 반복 이슈 성분·제품별 진행현황 관리

### 2. 개선하려는 업무와 이유

컨설팅 회신·규정 자료가 폴더에 들어와도 사람이 “새 회신 반영해줘”라고 말해야만 librarian이 취합본을 갱신했습니다. 반영 시점이 담당자 기억에 좌우되다 보니, 다음 COI 검토 시 screener가 참조하는 취합본이 최신이 아닐 위험이 있었습니다.

또한 취합본에 54건이 쌓였는데도 어떤 성분이 여러 나라에서 반복 걸리는지, 어떤 제품이 지금 어느 단계인지는 아무도 집계해서 보여주지 않아 데이터가 인사이트로 이어지지 못했습니다.

### 3. 개선 목표

**자동화 범위는 librarian 하나로 한정합니다.** 어떤 제품을 어느 나라 기준으로 검토할지는 수출 계획을 아는 사람만 판단할 수 있으므로, coi-reader·screener·reporter는 지금처럼 사람이 “OO 제품 OO국 검토해줘”라고 불러야 도는 구조를 그대로 유지합니다.

국가별 기준 폴더에 새 자료가 들어오면 librarian이 사람 요청 없이 자동으로 취합본에 반영하고, 그 반영 로그를 바탕으로 국가별 반복 이슈 성분과 제품별 진행현황을 보여주는 대시보드를 만듭니다.

### 4. 기대 효과

- screener가 항상 최신 취합본을 참조한다는 게 보장됨 — 반영을 깜빡해서 낡은 자료로 판정하는 위험 제거.
- 지금 데이터만으로도 6개 성분이 이미 2개국 이상에서 반복 걸리고 있다는 게 드러남(N-아세틸글루코사민은 3개국) — 매번 새로 걸리는 문제가 아니라 반복되는 문제로 관리 전환 가능.
- 담당자가 취합본 54행을 일일이 안 훑어도 제품별 지연·진행불가 상태를 한눈에 확인.

### 5. 사용할 기술

- 이미 등록 완료된 서브에이전트 4종(`.claude/agents` — librarian / coi-reader / screener / reporter).
- 폴더 감시 + 스케줄 자동 실행은 **librarian에만** 적용.
- librarian이 이미 자동 생성 중인 반영이력 로그를 대시보드 데이터 소스로 재사용.
- 집계·대시보드는 엑셀 피벗 또는 요약 화면.

### 6. 구현 방향

1. **RAW 가공:** Sheet1의 원료·국가·판정, 반영이력 로그를 표준화합니다. 비고 칸 텍스트 속 제품명(예: “관련 제품: 브이카리콜라겐(진행불가)”)을 정규 컬럼으로 분리합니다.
2. **지표 정의:** 성분별 등장 국가 수, 국가별 판정유형 비중, 국가별 자료 축적량, 제품별 진행단계.
3. **판정 기준 정의:** 2개국 이상 등장 시 “반복 이슈 성분”(현재 6건), 등재 5건 미만 국가는 “자료 부족 국가”(영국·말레이시아·인니), 이미 실사용 중인 “진행불가”/“성분 변경 조치” 표현을 표준 진행상태 값으로 채택합니다.
4. **대시보드 생성:** 뷰 ① 반복 이슈 성분 랭킹, 뷰 ② 제품별 진행현황 보드.
5. **자동화:** 국가별 `기준/` 폴더를 감시해 새 파일 발견 시 librarian만 자동 실행 → 취합본·반영이력 자동 갱신 → 두 대시보드 뷰도 함께 갱신합니다. coi-reader/screener/reporter는 여전히 사람이 국가·제품을 지정해야 시작되는 on-demand 단계로 남깁니다.

## 8. 주간업무보고 통합 대시보드

출처: 텍스트 제출 3 (추가 제출)

### 1. 프로젝트명

주간업무보고 통합 대시보드

### 2. 개선하려는 업무와 이유

CX·구매·QM팀의 주간보고가 팀마다 다른 양식으로 올라와, 현황을 파악하려면 파일 세 개를 각각 열어 읽어야 합니다. 같은 사안도 팀마다 다르게 표현해서 한 건인지 여러 건인지 구분이 어렵고, 정상 진행 건과 문제 건이 한 문단에 섞여 있어 급한 건을 놓치기 쉽습니다.

지난주 이슈가 해결됐는지 확인하려면 과거 파일을 다시 뒤져야 합니다. 이를 한 화면으로 모아 취합 작업을 줄이고, 특이건 표시는 시스템이 대신하도록 하려 합니다.

### 3. 개선 목표

- 팀별 보고 파일을 하나의 통합 표로 자동 취합하는 구조 마련.
- 최소 공통 입력항목(주차·팀·구분·대상·내용·상태·담당자)을 정해 팀별 양식 통일.
- 지연·클레임·부적합 등 특이건을 시스템이 자동으로 걸러 표시.
- 이슈별 이력을 주차 단위로 이어 붙여 미해결 건이 몇 주째인지 확인 가능하게 설정.

### 4. 기대 효과

- 여러 파일을 오갈 필요 없이 한 화면에서 현황 확인(보고 파일 3개 → 화면 1개).
- 특이건을 눈으로 찾던 일이 없어져 급한 건 누락 위험 감소.
- 원료 입고 지연 → 생산 차질 → 납기 지연처럼 팀에 걸친 건을 하나로 연결해 파악.
- 팀은 정해진 칸만 채우면 되어 보고서 작성 부담 감소.
- 담당자가 바뀌어도 시스템에 기준과 이력이 남아 관리 방식이 그대로 유지됨.
- 쌓인 데이터를 그대로 집계해 월간·분기 보고에 재사용 가능.

### 5. 사용할 기술

1. **데이터 취합(Python + pandas):** 팀별 파일을 읽어 하나의 표로 합치고 계산하는 부분.
2. **문서 읽기(openpyxl + python-docx):** 엑셀의 병합셀·서식, 워드 보고서의 본문 텍스트를 뽑아내는 도구.
3. **데이터 저장(JSON 파일):** 별도 데이터베이스 없이 취합 결과를 파일 하나로 보관하는 방식.
4. **대시보드 화면(단독 HTML + JavaScript):** 설치나 인터넷 없이 파일 하나만 열면 되는 화면. 사내망에서 안전.
5. **사내 배포(기존 사내 웹서버):** 이미 운영 중인 서버의 웹 폴더에 파일만 올려 링크로 공유.
6. **자동 실행·메일 발송(윈도우 작업 스케줄러 + SMTP):** 정해진 시각에 스스로 취합하고 특이건 요약을 메일로 보내는 장치.

### 6. 구현 방향

1. 세 팀 보고서를 나란히 놓고 겹치는 항목만 추려 공통 입력 템플릿(엑셀 1시트)을 먼저 배포합니다.
2. 팀별 파일을 주차 폴더에 모아두고, 스크립트가 폴더를 읽어 통합 표로 변환합니다.
3. 팀별 읽기 코드를 분리해, 한 팀 양식이 바뀌어도 그 팀 부분만 수정하도록 구성합니다.
4. “완료·종결·Closed”처럼 팀마다 다른 표현을 하나로 통일하는 기준을 코드에 고정합니다.
5. 화면은 상단 요약 카드(총 보고건수·특이건·미해결·신규), 팀별 탭, 특이건 필터, 상세 테이블로 구성합니다.
6. 특이건 판별은 상태값·키워드·2개 팀 이상 언급·3주 연속 진행중 등 단순 규칙으로 시작합니다.
7. 자동 취합 결과는 바로 공유하지 않고 담당자 확인 후 배포합니다.

## 9. 인플루언서 광고 제안 아웃리치 자동화

인플루언서 광고 제안 아웃리치 자동화 (부제: 스크리닝 + 컨택 메시지 초안 작성)

### 4. 기대 효과

- 후보가 바뀔 때마다 제안 메시지를 처음부터 쓰는 시간이 줄어듭니다.
- 채널별 맞춤 문구라 컨택 응답률이 올라갈 가능성이 있습니다.
- 스크리닝→컨택까지 한 화면에서 관리할 수 있습니다.

### 5. 사용할 기술

- 이번에 만든 `ad_candidates.json` 등급표를 입력으로 재사용.
- 채널별 인기 콘텐츠(`인기영상TOP30`)를 참고해 메시지 초안을 만드는 별도 에이전트.
- 이번 대시보드와 같은 방식의 HTML 대시보드로 후보+메시지 초안을 함께 표시.

### 6. 구현 방향

1. 1순위 후보 6곳의 채널 정보·최근 인기 영상을 정리한 입력 자료를 만듭니다.
2. 채널별로 “왜 이 채널에 제안하는지, 어떤 제품이 잘 어울리는지”를 담은 메시지 초안을 자동 생성합니다.
3. 07번 후보 리스트 표 옆에 생성된 메시지 초안을 나란히 보여줍니다.
4. 사람이 초안을 검토·수정한 뒤 실제 발송은 사람이 직접 합니다.
5. 응답이 온 채널은 등급표에 컨택 상태(제안함/협상중/완료)를 추가로 표시합니다.

## 10. 신제품 자동 감지 & 상품설명서 자동 생성 시스템

출처: 텍스트 제출 4 (추가 제출)

### 1. 프로젝트명

신제품 자동 감지 & 상품설명서 자동 생성 시스템

### 2. 개선하려는 업무와 이유

분기마다 특판 상품 제안 리스트를 업데이트하는데, 신제품이 나올 때마다 직접 확인하고 수기로 리스트에 추가하고 있는 상황입니다. 해당 파일은 상시몰 상품 제안 시에도 참고하고 있어 수시 업데이트가 필요합니다.

또한 상품별 셀링포인트도 최신 이슈 및 심의문구 제외 여부를 사람이 직접 판단하여 작성 중이라, AI의 객관적인 지표와 시장조사를 통한 문구 기재가 필요합니다. 이 과정에서 신제품 기재 누락이나 수작업 리소스가 많이 드는 상황도 방지하고자 합니다.

- **현재 방식:** 수기 취합 + 수기 작성.
- **사용 범위:** 분기 특판뿐 아니라 상시몰 제안에도 참고 → 정확도·최신성·셀링포인트 필요.
- **개선 이유:** 신제품 추가 누락 위험 및 수기 추가 리소스 낭비 방지.

### 3. 개선 목표

1. 자사몰 기준 전체 상품 페이지를 최근등록순 정렬 기준으로 크롤링합니다. (수기 취합 개선)
2. 기존 보유 리스트와 비교해 신제품을 자동 식별합니다(없던 상품 = 신제품). (수기 취합 개선)
3. 신제품이 감지되면 상품 상세 정보를 자동 수집합니다. (수기 취합 개선)
   - 사람이 직접 크롬 확장 프로그램을 사용하여 취합하거나, 클로드 자동 취합이 가능한지 확인이 필요합니다.
4. 수집된 정보를 설정한 양식 그대로 엑셀 상품 설명서로 생성합니다. (수기 작성 개선)
5. 수집된 상품 정보 기반으로 최신 이슈·심의문구 기준을 반영한 셀링포인트 초안을 자동 생성합니다. (수기 작성 개선, 담당자 최종 검수는 유지)

### 4. 기대 효과

1. 신제품 등록 여부를 사람이 매번 확인할 필요 없이 자동 파악.
2. 특판 제안서 업데이트 시 상품 리스트 누락 방지.
3. 상품 설명서 작성 시간을 수집~정리~엑셀화까지 자동화하여 대폭 단축.
4. 사람마다 다른 셀링포인트 품질 편차 최소화(시장조사를 통한 보편화된 판촉 문구 사용).
5. 분기별 반복 작업의 업무 자동화로 리소스 최소화.

### 5. 사용할 기술

1. **크롬 확장 프로그램:** 자사몰 상품 리스트 페이지 크롤링(최근등록순 파밍).
2. **데이터 정리/취합 자동화:** 기존 상품 리스트(엑셀/DB)와 대조해 신규 항목만 추출.
3. **셀링포인트 자동 생성:** 수집된 상품 성분/효능 정보 + 최신 이슈 리서치를 바탕으로, AI가 심의문구 제외 기준에 맞는 셀링포인트 초안 작성.
4. **엑셀 자동 생성:** 수집한 상품 정보를 사용자가 지정한 양식에 맞춰 엑셀 시트로 출력.

### 6. 구현 방향

1. **크롬 확장 프로그램 제작:** 자사몰 전체상품 목록 페이지에서 최근등록순으로 상품 N개 기준 수집.
2. **제품 필터링:** 기존 특판 리스트(현재 보유한 엑셀)를 기준값으로 불러와 비교하고, 없는 상품만 “신제품”으로 분류.
3. **상세정보 수집:** 신제품으로 분류된 상품의 상세페이지에 들어가 설명서에 필요한 항목(성분, 용량, 가격, 이미지 등)을 추가 수집. 수집된 성분·효능 데이터와 최신 이슈를 바탕으로 심의문구 제외 기준에 맞춰 셀링포인트 문구 초안 작성.
4. **엑셀 양식화:** 분류된 상품 설명서 포맷(컬럼 구성, 시트 구조)에 맞춰 기존 엑셀 파일의 기존 상품 목록 하단에 자동으로 나열하여 업데이트.
5. **담당자 최종 확인:** 신제품 적합 유무 및 셀링포인트 문구 판촉 가능성, 심의 유형 등 기준 부합 여부 검수.

## 11. 브랜드마케팅팀 업무 리포트 자동화 에이전트

브랜드마케팅팀 업무 리포트 자동화 에이전트

### 2. 개선하려는 업무와 이유

팀원 9명이 각자 다른 시트에 일일 업무를 기록해, 매주 부장이 9개 시트를 하나씩 열어 우선순위 ‘상’ 업무와 지연·보류 건을 직접 찾아야 합니다. 사람이 눈으로 훑어보는 구조라 이슈 발견이 늦고, 취합 방식도 담당자마다 조금씩 달라 기준을 맞추기 어렵습니다.

### 3. 개선 목표

- 9개 개인 시트를 매일 자동으로 취합·표준화하는 구조 마련.
- 우선순위 ‘상’ 업무와 지연·보류 건을 에이전트가 먼저 걸러 보여주도록 설정.
- 업무유형·우선순위·상태 값을 코드(`99_설정`)에 고정해, 누가 입력해도 같은 기준으로 집계.

### 4. 기대 효과

- 주간 시트 취합에 걸리던 시간 대폭 단축, 매주 반복되는 수작업 제거.
- 지연·보류 건을 늦게 발견하던 문제 감소, 놓치는 이슈 최소화.
- 담당자가 바뀌어도 동일한 기준으로 집계·이력이 유지됨.
- 팀 전체의 우선순위 업무를 한 화면(대시보드)에서 확인 가능.

### 5. 사용할 기술

1. **데이터 취합/정제:** 엑셀 파싱 및 값 표준화 자동화(data-cleaner).
2. **분석:** 우선순위·지연 이상치 자동 판별(analyst).
3. **리포트 자동 생성:** 정해진 양식의 주간 리포트·이메일 초안 작성(reporter).
4. **오케스트레이터:** 전체 순서 관리 및 서브 에이전트 실행 조율.
5. **스케줄러:** 매일 저녁/매주 금요일 자동 실행.

### 6. 구현 방향

1. 팀원은 지금처럼 자기 시트에 일일 업무만 입력하며, 입력 방식 변경은 없습니다.
2. 오케스트레이터가 매일 저녁 data-cleaner → analyst 순서로 자동 실행합니다.
3. 우선순위 ‘상’ 업무 요약과 지연·보류 알림을 부장에게 매일 전달합니다.
4. 매주 금요일 오전, reporter가 주간보고서 초안과 이메일 요약을 자동 생성합니다.
5. 부장은 초안을 검토·보완만 하고, 최종 공유 여부는 직접 판단 후 발송합니다.

## 13. 상담 만족도 월간 대시보드 자동화 (Claude Skill)

출처: 이미지 7 하단 ‘과제 2 · 개인 프로젝트 기획서’ (추가 제출 이미지 1)

### 1. 프로젝트명

상담 만족도 월간 대시보드 자동화 (Claude Skill)

구글폼 응답·문자 발송 내역·상담결과이력 세 자료를 묶어, 월간 만족도 대시보드를 HTML과 PNG로 만드는 도구입니다.

### 2. 개선하려는 업무와 이유

매달 상담 만족도 조사 결과를 집계해 월간 보고 자료를 만드는 업무입니다.

- 응답을 내려받아 척도 환산, 항목별 평균 점수, 월별 추이를 엑셀로 계산합니다. 시간이 들고 옮겨 적는 과정에서 오류가 생깁니다.
- 월 응답 모수가 작은 편이라 낮은 점수 몇 건이 평균을 크게 흔듭니다. 평균 하나만으로는 점수가 왜 움직였는지 설명하기 어렵습니다.
- 회신 수와 발송 수가 서로 다른 시스템에 있어, 회신율을 낼 때마다 두 자료를 대조해야 합니다.
- 칭찬 의견이 들어와도 상담원을 바로 특정할 수 없습니다. 회신 고객의 연락처와 월 수천 건의 상담이력을 대조하는 것은 많은 시간이 소요됩니다.
- 집계 기준(제외 규칙, 회신율 분모 등)이 문서로 남지 않아 담당자나 시점에 따라 달라질 수 있습니다.

### 3. 개선 목표

- 점수·추이·분포·저점 응답·회신율·상담원 매칭을 자동 산출.
- 사람은 VOC 분류, 총평 작성, 판단이 갈리는 건의 확정만 담당.
- 산출물을 그 자리에서 수정하고 저장할 수 있게 해, 재작업 없이 보고까지 연결.
- 집계 기준을 설정 파일과 문서에 명시해 매달 동일하게 적용.
- 평균과 함께 점수 분포·개별 응답을 제시해, 작은 모수에서도 월 단위 보고가 가능하도록 구성.

### 4. 기대 효과

- 집계에 쓰던 시간을 해석에 쓸 수 있고, 옮겨 적는 과정이 없어 입력 오류가 사라집니다.
- 상담 유형·인입 채널·상담원 등으로 나눠 볼 수 있어, 점수가 왜 움직였는지 원인을 짚을 수 있습니다.
- 칭찬 의견에 담당자가 연결되어 개인 피드백과 우수 사례 공유로 이어집니다.
- 기준이 고정되어 월별·연도별 비교의 신뢰도가 확보되고, 담당자가 바뀌어도 유지됩니다.
- 매달의 총평과 VOC 분류가 파일로 쌓여 다음 달 비교의 기준이 됩니다.

### 5. 사용할 기술

- **스킬로 도구화:** 작업 순서와 판단 기준을 문서로 고정해 매달 재사용.
- **역할을 나눈 서브 에이전트 2개:** 집계 담당 / 분류 담당.
- 구글시트 응답 자동 수집, 연락처 정규화 대조(표기 방식이 제각각인 번호를 같은 번호로 인식).
- 인라인 차트로 대시보드 생성, 보고용 이미지 자동 출력.
- 산출물을 브라우저에서 수정하고 저장하는 기능.

### 6. 구현 방향

1. 매달 초 담당자가 문자 발송 내역과 상담결과이력을 올리고 실행하면, 구글폼 응답은 자동으로 가져옵니다.
2. **집계 에이전트**가 점수·추이·분포·회신율을 계산하고, 회신 고객의 연락처를 상담 이력과 대조해 담당 상담원을 자동 매칭합니다.
3. **분류 에이전트**가 상담 이력의 상담내용·처리사항을 읽어 저점 원인과 개선 요청을 유형별로 정리합니다.
4. 두 결과를 묶어 대시보드 한 장(HTML·이미지)으로 생성합니다.
5. 총평과 분석 의견은 자동 분석 결과를 바탕으로 사람이 직접 수정하고 확정합니다.
6. 확정된 리포트를 최종 HTML 또는 PNG로 생성해 월간 보고와 팀 공유에 활용합니다.

### 2. 개선하려는 업무와 이유

매주 물동량 현황 및 생산성 현황을 즉시 파악하지 못해 운영 효율성이 떨어집니다. 담당자가 매번 여러 원본 엑셀을 직접 열어 집계하는 데 시간이 들어가는 만큼, 이 과정을 자동화해 현황 파악 속도와 운영 효율성을 함께 끌어올립니다.

### 3. 개선 목표

리포트 산출 시간을 단축하고, 현황을 빠르게 파악해 무엇을 할지 판단하고 빠르게 의사결정할 수 있게 합니다.

### 4. 기대 효과

데이터 기반으로 빠르게 의사결정할 수 있게 되어 업무 효율성이 향상되고, 문제를 발견해 개선하는 데 걸리는 시간이 줄어듭니다.

- **데이터 처리:** 엑셀(WMS·구글시트 원본데이터).
- **분석:** 서브에이전트 구조 4개(재고분석·DPS분석·도착률분석·유통가공분석).
- **시각화:** HTML 대시보드.

### 6. 구현 방향

원문에 별도 ‘구현 방향’ 항목은 기재되어 있지 않습니다. 상단 소개에 제시된 흐름은 ‘엑셀 원본데이터 → 서브에이전트 분석 → HTML 시각화’입니다.

### 1. 프로젝트명

매번 수기로 월별, 품목, 수량, 금액별로 필터 또는 피벗을 통한 시각화 자료를 만들어 사용하고 있어, 업무 시간 단축 및 효율을 위해 개선하고자 합니다.

### 3. 개선 목표

로우데이터를 전달하면 월별, 품목, 수량, 금액별로 요약 및 정리한 후 대시보드 작업을 하여 보고 자료 및 내부 공유에 사용합니다.

### 4. 기대 효과

소요 시간을 단축하고, 요약된 자료를 그래프 등 시각화 자료로 쉽게 볼 수 있습니다.

### 5. 사용할 기술

데이터 취합, 에이전트, 대시보드.

### 6. 구현 방향

폴더에 로우데이터를 넣어두고, 에이전트를 통해 자료 정리 및 시각화 자료를 생성하여 최종 대시보드를 생성합니다.

## 16. 월마감 매출자료 일원화 및 마감 프로세스 자동화

출처: 이미지 9 (추가 제출 이미지 1)

### 1. 프로젝트명

월마감 매출자료 일원화 및 마감 프로세스 자동화

### 2. 개선하려는 업무와 이유

NC채널은 정기·일회성·단발성 채널이 섞여 있어 매월 30~40건의 마감 매출 처리가 필요합니다. 담당 업무 중 시간이 가장 많이 소요되며, 월 1회지만 영업일 4일 안에 끝내야 하는 마감 압박이 큽니다.

또한 채널별 자료 양식이 제각각이라 담당자 외에는 처리가 어렵고, 월초에 연차나 개인 사정이 생겨도 대체자를 구할 수 없는 구조입니다. 이 두 가지를 함께 해소할 수 있어 해당 업무를 선정했습니다.

### 3. 개선 목표

채널별로 흩어진 마감 자료를 하나의 공통 양식으로 일원화하고, ERP 업로드부터 거래명세서 발송까지 이어지는 마감 프로세스를 표준화합니다.

최종 목표는 담당자가 아니어도 마감을 대신 수행할 수 있는 수준까지 프로세스를 정리하는 것입니다. 즉, 개인 숙련도에 의존하던 업무를 누구나 인수인계받아 처리할 수 있는 업무로 바꿉니다.

### 4. 기대 효과

- 기존 4일 중 채널별 자료 취합·양식 변환에 소요되던 약 1일이 자동화로 사라져, 마감 기간 영업일 4일 → 3일로 단축(거래처 사정으로 지연되는 건 제외).
- 전 채널 자료가 한 양식으로 모여 취합·검증 시간 절감.
- 담당자 부재 시에도 대체 인력이 동일한 결과로 마감 가능.
- 처리 방식이 고정되어 담당자별 편차 및 누락 리스크 감소.

### 5. 사용할 기술

데이터 취합 + 서브에이전트 + 대시보드 + 메일 자동 발송(거래명세서).

### 6. 구현 방향

전 채널 마감 자료를 공통 양식 한 파일로 합치고, 이를 그대로 ERP 업로드 양식으로 전환합니다.

업로드 후 발생한 미매핑 건은 자동으로 분리·검증해 재업로드하고, 확정된 매핑 정보는 기준값으로 축적해 다음 달부터는 미매핑이 반복되지 않도록 합니다.

마감이 확정되면 대시보드로 채널별 마감 현황을 보여주고, 거래명세서를 자동 발송합니다.

## 20. SB 작성 보조 도구 (Claude Skill)

출처: 텍스트 제출 9 (추가 제출)

### 1. 프로젝트명

SB 작성 보조 도구 (Claude Skill)

과제 1의 `sb-check`와 짝을 이루어, SB 작성 전의 착수 체크리스트와 작성 후의 정책서 정합성 변경안 제안 두 단계를 채우는 도구입니다.

### 2. 개선하려는 업무와 이유

과제 1의 `sb-check`는 SB를 다 쓴 뒤 검토해줍니다. 그러나 재작업과 혼선의 상당수는 SB를 잘못 그려서가 아니라, 회의에서 들은 요건을 SB에 무엇을 담아야 할지 정리하지 않은 채 작성을 시작하거나, SB가 바뀌었는데 노션 정책서 반영을 잊어서 생깁니다.

- 구두 요건을 메모 수준으로만 남기고 바로 SB를 작성해 구성요소·예외 케이스가 빠집니다. `sb-check` 사후 검수도 SB에 아예 반영되지 않은 요건은 잡지 못하는 사각지대가 존재합니다.
- SB가 바뀌어도 노션 정책서 반영은 전적으로 수작업·기억에 의존해, SB(최신)와 정책서(과거 기준)가 다른 말을 하는 상태가 방치됩니다.

### 3. 개선 목표

- **파트 A:** 회의 메모를 SB 착수 전 체크리스트(구성요소/케이스/모호한 지점)로 변환합니다.
- **파트 B:** SB 작성 후 관련 노션 정책서와 자동 대조해 변경안(초안)만 제안합니다. 실제 반영은 사람이 노션에서 직접 확인 후 수행합니다.

### 4. 기대 효과

- SB 재작성·개발 재작업 감소(`sb-check` 지적 건수 감소로 효과 직접 측정).
- 정책서 업데이트 누락 방지 및 SB↔정책서 정합성 유지.
- 반복 확인 질문·변경 이력이 개인 업무 자산으로 축적.

### 5. 사용할 기술

- **Claude Skill:** `sb-check`의 4개 렌즈를 ‘사전 확인 질문’으로 역변환.
- **AskUserQuestion:** 모호한 지점만 되묻기.
- 비정형 회의 메모 구조화.
- **Notion MCP 연동:** 조회 전용 — 쓰기는 항상 사람 승인. 실제 정책서 반영은 사람이 직접 수행.
- 문서 대조(diff) 로직.

### 6. 구현 방향

**파트 A — SB 착수 전 체크리스트**

1. `sb-check` 지적 패턴을 사전 질문으로 뒤집습니다.
2. 체크리스트 생성 스킬을 작성합니다.
3. 실제 요건 1건에 적용합니다.
4. `sb-check`로 효과를 측정합니다.

**파트 B — 정책서 정합성 변경안 제안**

1. 화면·업무 영역별 정책서를 매핑합니다.
2. SB↔정책서를 대조해 ‘현재 문구 → 제안 문구 → 근거’ 변경안 리포트를 생성합니다.
3. 실제 SB로 시범 적용합니다.
4. 승인 절차(항상 수동 반영)를 확정합니다. (1~2주)

### 과제 1과 연결되는 업무 흐름

1. **구두 요건 + 과제 2 파트 A:** 회의 메모 → 화면 구성요소·케이스·모호한 지점 체크리스트.
2. **SB(피그마) 작성:** 체크리스트를 보면서 빠짐없이 작성.
3. **과제 1 `sb-check` 검수:** 완성된 SB를 4개 렌즈로 사후 검토.
4. **과제 2 파트 B 변경안 제안:** SB↔노션 정책서 대조 → 변경안 초안. 반영은 사람이 직접 수행.

`sb-check`가 ‘다 쓴 SB를 검사’한다면, 이 도구는 ‘쓰기 전 무엇을 담을지 정리’하고 ‘쓰고 난 뒤 정책서와 어긋난 곳을 찾아 제안’하여 하나의 업무 흐름을 앞뒤로 감싸는 짝 도구입니다.

### 자동화 범위 및 사람의 검토 원칙

정책서는 자동으로 고쳐 쓰지 않습니다. 노션 정책서는 다른 사람도 참조하는 공유 문서라, AI가 맥락을 놓치고 잘못 반영하면 피해가 SB 한 장보다 큽니다. 따라서 파트 B는 항상 ‘변경안 제안’까지만 하고, 실제 노션 반영은 작성자가 직접 확인하고 수행합니다. 이는 `sb-check`의 ‘판단은 사람이 한다’는 원칙과 같습니다.

## 21. 서버 로그 통합 모니터링 & 자동 보고 시스템

출처: 텍스트 제출 10 (추가 제출)

### 1. 프로젝트명

서버 로그 통합 모니터링 & 자동 보고 시스템

### 2. 개선하려는 업무와 이유

웹서버·DB서버·API서버가 분리되어 있어, 장애나 이상 징후를 확인하려면 서버별로 SSH 접속 후 로그를 각각 열어보고 눈으로 훑어야 합니다. 슬로우쿼리, 반복 에러, API 5xx 급증 같은 패턴은 사람이 놓치기 쉽고, 발견도 사후(장애 발생 후)에야 이루어지는 경우가 많습니다.

쇼핑몰 특성상 장애가 곧 매출 손실로 직결되는데, 로그 확인이 수동·비정기적이라 조기 발견이 어렵고, 매번 반복되는 로그 확인·요약 작업에 실무 시간이 소모됩니다.

### 3. 개선 목표

- 웹/DB/API 서버 로그를 한 곳으로 자동 취합.
- 에러코드·슬로우쿼리·트래픽 이상 패턴 자동 분류 및 우선순위 판단.
- 사람이 보기 쉬운 요약 리포트/대시보드 자동 생성(매일 또는 특정 주기).
- 심각도 높은 이슈는 Slack 등으로 즉시 알림.

### 4. 기대 효과

- 매일 반복되던 로그 확인·정리 시간 대폭 절감.
- 장애 징후 조기 발견으로 대응 시간 단축, 매출 손실 리스크 감소.
- 비개발 직군(운영팀 등)도 이해할 수 있는 형태로 서버 상태 공유 → 커뮤니케이션 비용 감소.
- 로그 분류 기준이 스킬 문서로 축적되어 담당자 교체 시에도 지식 손실 없음.

### 5. 사용할 기술

- **서브에이전트:** 로그 분석/이상 패턴 탐지를 전담하는 에이전트 구성.
- **스킬 md 문서:** 에러코드별 조치 기준, 슬로우쿼리 임계값 등 판단 규칙 문서화·재사용.
- **데이터 취합:** 여러 서버(웹/DB/API)의 로그 파일을 하나의 파이프라인으로 취합.
- **대시보드 제작:** 취합된 데이터를 시각화한 일일/주간 대시보드.
- **Python:** 서버별 로그 수집·1차 가공 배치 스크립트, 필요 시 윈도우용 알림 프로그램.
- **커넥터/스케줄링(추가 학습):** Slack 커넥터로 심각 이슈 자동 알림, 크론 스케줄링으로 정기 실행 자동화.

### 6. 구현 방향

1. **수집:** Python 스크립트로 웹서버/DB서버/API서버 로그를 정기적으로 가져와 취합합니다.
2. **규칙 정의:** 에러코드, 슬로우쿼리 기준, HTTP 5xx 비율 등 판단 기준을 스킬 md로 정리합니다.
3. **분석:** 서브에이전트가 스킬 문서 기준으로 로그를 분석해 이슈를 우선순위별로 분류합니다.
4. **시각화/보고:** 분석 결과를 대시보드(또는 문서)로 자동 생성합니다.
5. **알림/자동화:** 심각도 높은 이슈 발생 시 Slack으로 알림을 보내고, 전체 파이프라인은 스케줄러로 매일 자동 실행합니다.
6. **검증:** 과거 실제 장애 로그로 테스트해 탐지율을 확인한 후 점진적으로 적용합니다.
